RULE 01

is-a transitivity

If A is-a B and B is-a C, infer A is-a C. This enables class hierarchy traversal.

A → is-a → B → is-a → C
RULE 02

Property inheritance

Descendants inherit applicable properties from their ancestor classes unless an explicit override is present.

Child inherits Parent.properties
RULE 03

part-of transitivity

If A is part of B and B is part of C, infer that A is part of C in a transitive containment model.

A part-of B; B part-of C
RULE 04

Default reasoning

Typical assumptions apply in the absence of contrary evidence.

Normally: birds fly
RULE 05

Exception precedence

A more specific exception defeats a general default conclusion.

Penguin exception: cannot fly

Ontology studio

Explore the building blocks of a formal semantic model.

Core relationship types

is-a TAXONOMIC

Subclass or instance-of relationship. Used for classification, inheritance, and transitive hierarchy reasoning.

Cat is-a Mammal; Mammal is-a Animal
part-of MERONYMIC

Component-to-whole relationship. Whether it is transitive depends on the domain semantics and modelling assumptions.

Wheel part-of Car
has-property ATTRIBUTE

Connects an entity to a characteristic or value.

Student has-property student_id
related-to ASSOCIATION

A general association when no more precise relation is available. Prefer specific predicates where possible.

Researcher related-to Publication

Triple

(Alice, studies, AI)
Ontology axiom

A formal constraint or statement about classes, properties, and individuals.

Inference

A conclusion derived from existing facts and formal rules.

Important reasoning principles

Transitivity

Some relations propagate through chains. Example: is-a subclass chains.

Inheritance

Specific concepts receive properties from general concepts.

Monotonic reasoning

Adding premises never invalidates a previously valid conclusion in classical monotonic logic.

Non-monotonic reasoning

New evidence can retract a previously reasonable default conclusion.

Open-world assumption

Missing information is not automatically considered false.

Closed-world assumption

In some systems, facts not present are treated as false for a defined database scope.

PROJECT OVERVIEW

Domain Knowledge Graph Builder & Semantic Reasoning Explorer

Develop a knowledge graph for a selected domain. Represent concepts as nodes and semantic relations as typed edges. Implement inference over graph structure rather than storing every answer as an isolated fact. Demonstrate inheritance, property propagation, defaults, and exceptions with an explainable query interface.

Problem statement

Conventional lookup systems often retrieve only explicitly stored facts. They do not automatically exploit class hierarchies, part-whole structures, or defeasible knowledge to derive new conclusions.

Objectives

Model a domain ontology, define semantic relations, implement graph traversal and inference, demonstrate exception handling, and provide natural-language or structured queries.

Expected outcome

An interactive graph-based application that answers semantic questions, displays inferred facts, and explains the paths and rules behind its conclusions.
